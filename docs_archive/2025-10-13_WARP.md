# WARP.md

This file provides guidance to WARP (warp.dev) when working with code in this repository.

## Project Overview

This is the **Museum Information System** (Информациони систем Природњачког музеја у Београду) - a modular Flask web application for the Natural History Museum in Belgrade. The system integrates two main subsystems into a unified interface with shared authentication.

**Technology Stack:**
- Python 3.13+ with Flask framework
- MySQL (for timesheet system) + SQLite (for mineral database)
- Gunicorn for production deployment
- Bootstrap 5 for responsive UI
- ReportLab for PDF generation
- Pillow for image processing

## Architecture Overview

### Core Components

The system follows a **modular monolith** pattern with three main layers:

1. **Main Application** (`app.py`) - Central integration layer with authentication
2. **Timesheet System** (`localSQLtesting/`) - Employee work tracking subsystem
3. **Mineral Database** (`PrirodnjackiMuzej/`) - Museum collection management subsystem

### Key Integration Points

- **Shared Authentication**: Main app handles login/logout, subsystems inherit sessions
- **Module Access Control**: Role-based access with configurable dashboard widgets
- **Unified Navigation**: Single entry point at port 5000, subsystems run on different ports
- **Image Storage Engine**: Centralized image management with API endpoints
- **PDF Export System**: Multi-format document generation (certificates, reports, collections)

### Data Flow Architecture

```
Main App (5000) → Authentication → Dashboard → Module Selection
    ↓
    ├── Timesheet System → MySQL (employee work data)
    ├── Mineral Database → SQLite (5,997 mineral specimens)
    ├── Image Storage → File system + database metadata
    └── PDF Export → ReportLab documents
```

## Code Organization Principles

### Language Preferences
- **ALWAYS use Serbian Cyrillic** versions of timesheet components (`*_cyrillic.py`)
- Prefer `app_cyrillic.py` over `app_refactored.py`
- Prefer `ui_components_cyrillic.py` for UI development
- All user-facing text must be in Serbian Cyrillic

### Authentication System
The main app uses **fallback authentication** when MySQL is not configured:
- Admin: `admin` / `admin123` 
- Test user: `test` / `user`
- Production uses full employee database integration

### Module Access Control
Access is controlled via `MODULE_ACCESS` configuration in `app.py`:
- `default_access: True` = available to all users
- `authorized_users` = explicit allowlist
- Admin role has universal access
- Dashboard widgets are user-configurable

## Key Development Areas

### Employee Data Management
- **Source of Truth**: `localSQLtesting/listazaposlenih.txt` (42 employees across 7 departments)
- Employee seeding: `python employees_seed.py`
- Department structure is critical - maintain official Serbian names
- Analytics system tracks working hours (input numbers = actual hours worked)

### Image Storage System
- **Core Files**: `image_storage_engine.py`, `image_api.py`, `image_database_manager.py`
- Handles batch uploads, metadata extraction, and API endpoints
- Storage location: `storage/` directory with database metadata
- Image matching algorithms for specimen identification

### PDF Export System
- **Core File**: `pdf_export.py`
- **Test File**: `test_pdf_export.py` - run this to verify PDF generation
- Generates: collection catalogs, visitor reports, research projects, specimen certificates
- Uses ReportLab with Serbian Cyrillic font support

### Mineral Database Integration
- **Database**: `PrirodnjackiMuzej/prirodnjacki_muzej.sqlite` (5,997 specimens)
- **RRUFF Integration**: External API for mineral data validation
- **Excel Import**: Batch processing of collection data
- **Specimen Matching**: Automated categorization algorithms

### Exhibitions Database
- **Purpose**: Historical record of gallery exhibitions (not physical exhibits/artifacts)
- **Data Source**: `data/exhibitions.json` - chronological timeline of museum exhibitions
- **Scope**: Gallery exhibitions and touring exhibitions with visitor analytics
- **Key Fields**: title, dates, curator, visitor count, description, type, location
- **Important Distinction**: 
  - **Exhibitions Database** = temporary displays/shows ("изложба")
  - **Exhibits Database** = permanent collection artifacts ("експонат")
  - These are separate databases with different purposes

## Important Conventions

### Serbian Business Practices
- **Serbian Holidays**: Orthodox Easter calculation via `serbian_holidays.py`
- **Working Hours**: Input numbers represent actual hours worked (8 = full day)
- **Month Names**: Use Serbian Cyrillic ("Јануар", "Фебруар", etc.)
- **Department Names**: Use official museum department names in Cyrillic

### Database Conventions
- **Timesheet System**: Uses MySQL with specific schema for work categories
- **Mineral Database**: SQLite with 20+ fields per specimen record
- **Image Metadata**: Separate tracking for storage paths and specimen associations
- **Analytics Data**: Tracks previous month comparisons ("Урађено у прошлом месецу")

### File Structure Patterns
- Configuration files in `config/` subdirectories
- Logs in `logs/` with separate files per subsystem
- Static assets in `templates/` and `static/` directories
- Data files in `data/` directory
- Backup systems for database migrations

## Testing and Quality

- Check logs in `logs/` directory for each subsystem

## Production Considerations

### Deployment Architecture
- **Main App**: Port 5000 (public-facing)
- **Mineral Database**: Port 5001 (internal API)
- **Gunicorn**: Production WSGI server with multiple workers
- **Static Files**: Served directly by Flask in development

### Performance Notes
- Large mineral database (5,997+ records) requires efficient querying
- Image storage system handles batch uploads up to hundreds of files
- PDF generation can be memory-intensive for large collections
- Analytics queries may be slow for extensive date ranges

### Security Considerations
- Role-based access control with admin/employee distinction
- Session-based authentication across subsystems
- File upload validation for image storage
- Database credential management via environment variables

## Common Development Tasks

When working with this system:

1. **Adding New Museum Modules**: Update `MODULE_ACCESS` in `app.py`, create routes, add to navigation
2. **Employee Data Changes**: Update `listazaposlenih.txt`, run `employees_seed.py`
3. **UI Modifications**: Use Serbian Cyrillic, maintain Bootstrap 5 compatibility
4. **Database Changes**: Handle both MySQL and SQLite schema updates
5. **Image Processing**: Extend `image_storage_engine.py` for new specimen types
6. **PDF Templates**: Modify `pdf_export.py` for new document types

Remember: This is production software for an active museum with 42 employees. Maintain data integrity and preserve Serbian cultural context in all user-facing elements.
