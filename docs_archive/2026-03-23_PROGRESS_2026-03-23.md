## Security Fixes

### Critical: Image API (was completely open to anonymous access)
- All routes now require `@login_required` or `@admin_required`
- Delete, metadata, entity images, stats — elevated to admin-only
- Upload checks module-level access per database collection
- Backup/restore require admin, receive endpoint uses `X-Backup-Token` for service-to-service auth
- Backup path validation uses `Path.is_relative_to()` (not string prefix)
- Backup name sanitized against safe slug regex
- 22 security tests added (`test_image_api_security.py`)

### Critical: SQL Injection
- Eliminated all f-string SQL patterns across 9 production files
- Fixed: `mineral_database.py`, `mineral_database_pg.py`, `rruff_database.py`, `rruff_database_pg.py`, `mail_client.py`, `timesheet_repository.py`, `archive_signature_blueprint.py`, `image_database_manager.py`, `bird_ringing_database.py`
- All ORDER BY, WHERE, LIMIT clauses now use validated whitelist + string concatenation
- Zero `execute(f"` or `text(f"` patterns remain in production code

### High: Image Upload Atomicity
- `store_image` now cleans up files on disk when DB insert fails
- Prevents orphaned files with no metadata record
- Concurrent uploads use uuid4 temp filenames (prevents overwrites)
- Backup URL fixed (`/api/backup/image` → `/api/images/backup/receive`)
- `backup_to_server` returns false if any image fails

### High: Deployment Consistency
- `start_production.sh` aligned to `127.0.0.1:8000` (matching gunicorn.conf.py and nginx)
- Admin log viewer fixed: was reading `main_app.log`, actual file is `museum_info_system.log`
- `pg_dump` now uses `DATABASE_URL` instead of hardcoded username/database

### Medium: Admin Settings
- `session_timeout` now applies to `PERMANENT_SESSION_LIFETIME`
- Settings loaded from JSON on app startup (shared across workers)
- Multi-worker warning shown when settings saved

### Medium: Rate Limiting
- Production config warns/fails when in-memory rate limiting used with multiple workers
- Gunicorn workers configurable via `WORKERS` env var

### Medium: Mail Credentials
- Missing encryption key now raises RuntimeError instead of silently generating new one
- Prevents undecryptable saved credentials

## Production Hardening (external changes integrated)

Additional architectural improvements were integrated:
- **Shared state via PostgreSQL:** Security settings, module access, dashboard preferences stored in `app_shared_settings` table
- **Redis session storage:** Production config requires Redis for sessions and rate limiting
- **Image storage abstraction:** `ImageStorageBackend` with local filesystem + S3 backends, per-path instance isolation
- **Mail credentials to PostgreSQL:** Per-user encrypted mail settings with auto-migration from legacy files
- **CSRF narrowing:** Only upload and backup receive endpoints exempt (was entire blueprint)
- **Background worker:** Separate `background_worker.py` process for recurring jobs
- **Fail-closed production:** Config raises RuntimeError if Redis unavailable with multi-worker setup
